# Explicit filesystem destinations, no Git requirement

Owner decision, 26 November: work on ordinary files whether tracked or not. No implicit commits, index reads, pushes, or Git executable. A caller explicitly selects `--in-place` or `--into DIR`; preview has no destination and never writes source files. Support a caller-created empty output directory. Do not merge into or overwrite unrelated destinations. `refs --root DIR PREFIX NEEDLE`, `preview --root DIR PREFIX NEEDLE REPLACEMENT`, and `apply --root DIR PREFIX NEEDLE REPLACEMENT --review ID (--in-place | --into DIR)` use literal/v1, not language-aware references. Directories and options are separate arguments, never shell commands. Scope is a validated relative directory prefix with trailing slash; the root is a trusted caller-selected directory. Audit/review IDs bind the source, admitted scope, request, profile and exact candidate. A changed request or source needs a new preview. Tracked status is irrelevant.

**Acquisition:** walk only the explicit prefix, including hidden entries there; preserve relative names underneath the root. Outside-prefix files are not claimed as part of the inventory. Validate ordinary UTF-8 file/path profiles and count bytes and visited entries (including directories). Empty or zero-match inputs must not imply a completed modification. Refuse unsupported/symlinked components and special files rather than following or silently ignoring them. Snapshot means captured immutable bytes, not simultaneous observation of a changing directory.

**Authority and concurrency:** local Linux filesystem under the caller's control; a trusted directory hierarchy, no hostile namespace changes and one host-authorized writer throughout apply are preconditions. Refuse a concurrent cooperating apply; compare actual inventory/content and file metadata before effects. Recheck each target before replacement. Neither a content comparison nor an advisory lock excludes unrelated concurrent writers. On a general tree under uncontrolled concurrent editing, use output to a separate destination; no isolation or stale-write guarantee against outsiders. Use safe directory-relative operations/no-follow where available. Never follow a link, truncate a live target, or publish a partial file. Refuse unsupported inode/metadata cases rather than silently discarding properties. Explicitly state permissions/metadata preserved and excluded.

**Effects:** prepare and check every candidate before file effects. In-place: replace changed files only using same-directory private temporaries and rename; the successful rename is the visibility point for that file. Do not imply multi-file atomicity or durable power-loss semantics. Into: create or use an empty destination independent of the input, preserve the scoped layout and unchanged scoped files, never clobber an existing unrelated file. A failure before effect is Refused; a known prefix of effects is Partial (identify paths); ambiguous/crashed outcomes are Unknown until reconciliation. Describe recovery and provide a deterministic comparison against the reviewed base/candidate before retrying; no blind rollback of external changes. Test stale input, no-change, destinations, actual partial effects, conflicting writers and process death. No automatic run policy/receipts: that remains Writfold's domain. Re-read writfold.dev before closing the milestone.

### What this profile supports

Linux `openat2` is required (5.6 or newer). Use a caller-controlled ext-family, tmpfs or overlay filesystem. Other filesystem types refuse, including Windows-mounted WSL paths and network filesystems. Scope components use the fixture ASCII path profile; `.git`, links, mount crossings within scope, nonregular files, visible xattrs/ACLs, special mode bits and unsupported inode flags refuse. Hidden privileged attributes, namespace changes by outsiders and power-loss behavior are not qualified. File bytes are UTF-8 with no normalization. Limits include 32 directory levels, 256 directories, 256 files, 8 MiB per input file and 32 MiB total. New directories are private (`0700`); replaced/copied files retain ordinary permission bits and UID/GID. Times, inode numbers, links, and directory ACLs are not copied. Files to be replaced or copied must belong to the invoking user.

No-change does not populate an output directory. For a real change, `--into` materializes the entire scoped layout, including empty directories and files with no matches, **not** everything under the source root. The output must not overlap the input; its parent must already exist. Work directories are private and local to each target parent. Cooperating invocations lock directory inodes and ancestors; unrelated writers are not fenced. File data is synced during staging; no directory-sync or power-loss durability contract is made.

### Recovery after interruption

Save the complete JSON from `preview` somewhere **outside the prefix** before applying. If `apply` reports `Partial`/`Unknown`, or dies without a complete response, stop other writers. Use the *saved* `resources`, not a new preview of the mixed tree. Compare each current regular file's SHA-256 with both its `base_sha256` and `output_sha256`; classify it as base only, output only, both, missing or conflict. Check the full set of names, the saved file mode/UID/GID and expected directories, including unexpected entries. A `Complete` response lists successful file renames; do not infer that a missing response means nothing changed. Inspect any `.plyrune-stage~PID` directories; remove only staging files you can positively identify. Preserve partial `--into` output and choose a new empty directory; for in-place edits reconcile conflicting or missing files separately before previewing and authorizing a new task. Never blindly retry, roll back, or apply fresh search/replace to a mixed tree (the replacement might itself contain the needle).
